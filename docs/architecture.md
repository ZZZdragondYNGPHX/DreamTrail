# 架构

## 模块职责

`core` 定义游戏状态和内容，并执行确定性战斗、成长、离线结算与存档校验。它不依赖 Android、Room 或系统时钟。

`app` 使用 Jetpack Compose 展示旅途、角色、伙伴、营地、图鉴和守夜界面。`DreamTrailViewModel` 管理交互状态，`GameRepository` 协调数据库事务、规则调用与备份操作。

## 旅程与收益

出发时固定路线、策略、随机种子、装备、被动、营地等级、收藏加成、伙伴、茶饮和夜象。旅途中调整配置只影响下一次出发。

`DurationResolver` 在同次设备启动中优先使用单调时钟；跨重启使用 UTC 时间并限制异常跨度。`RewardBudgetCalculator` 分配单次 12 小时、滚动 24 小时内 8 小时的有效收益时间。

基础资源按有效秒数和定点余量累计。探索事件每 5 分钟一个节点，不足一个节点的时间保留到下次结算；单次最多模拟 96 个节点。事件冷却、区域调查与首领进度使用有效探索时间。

战斗最多 20 回合。连续遭遇失败后转为安全搜集，保留已获得的收益。装备、事件、风物和奇遇使用独立的随机数流。

## 数据与恢复

Room 保存角色、背包、旅程、战报、奖励账本、收益预算、探索记录和设置。副词条与出发夜象分别持久化，不依赖展示文本或再次推算。

结算先固定结束时间，再在事务中写入战报、账本和进度。重启恢复使用已固定的结束时间；账本以 `(sessionId, rewardKind)` 为主键，重复结算返回原战报。

`SaveBackupCodec` 使用 JSON 和 SHA-256 校验和，检查资源、装备栏位、星图前置条件和配置引用。导入和自动快照恢复共用同一条数据替换流程。导入的旅程废弃原设备的单调时钟锚点。

当前规则和内容版本为 4，只支持当前版本的存档与旅程。

## 内容维护

内容集中在 `ContentCatalog`，由 `ContentValidator` 校验编号、引用、区域覆盖和进度条件。纯函数操作集中在 `ProgressionEngine`；界面通过仓库修改状态。

`SleepDataProvider` 是可注入的睡眠数据接口，默认实现为手动模式。后续接入睡眠数据时，通过现有账本补发基础 3% 祝福与最高 8% 祝福之间的差额。
